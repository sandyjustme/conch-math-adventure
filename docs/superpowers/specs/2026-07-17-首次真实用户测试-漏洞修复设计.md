# 首次真实用户测试 — 漏洞修复设计

## 背景

2026-07-17 第一次真实孩子（初一厌学生）测试。孩子在 iPad 上使用 PWA，**完美避开所有学习路径**：

1. 跳过 AI 诊断 → 直接刷潜水算术
2. 利用答错提示「显示精确答案」的漏洞，反复拖对应位置得碎片，10 分钟攒了 40 珍珠
3. 在古深海遗迹中完全不看数学内容，把圆放进格子 → 点下一步 → 纯拼图通关

## 修复总览

| 漏洞              | 修复方向                        | 核心设计                                                                               |
| ----------------- | ------------------------------- | -------------------------------------------------------------------------------------- |
| 跳过诊断          | 首次使用强制路径 + 倍率差引导   | 咖啡馆除「今日探险」外全部锁定；诊断完成后 AI 跳转的活动给全额碎片，自己点入口的给 1/5 |
| 答错泄题 + 刷珍珠 | 隐藏精确答案 + 答错倒扣         | hint 只显示方向不显示终点；过关碎片 = max(0, 1 - 错×0.1)；答错 10 次以上归零           |
| 遗迹不验证理解    | 拖放变成数学操作 + TTS 结果朗读 | 放错弹回；放对后 TTS 朗读数学含义，朗读完才可进入下一关                                |

### 新增：今日探险碎片奖励

目前 AI 对话完全不给碎片（只给珍珠）。加碎片奖励让「先聊再练」比「直接刷」更划算。

| 行为                      | 珍珠 | 碎片   |
| ------------------------- | ---- | ------ |
| 每轮对话                  | —    | 🌟 0.5 |
| 真正想通（AI `REWARD`）   | 💎 1 | 🌟 2   |
| 学懂跳转（AI `PRACTICE`） | —    | 🌟 3   |

## 一、咖啡馆入口锁

### 1a. 首次使用强制诊断

**组件**: `CafeHall.tsx`

- 新增 store 字段: `diagnosticsCompleted: boolean`（默认 false，持久化到 IndexedDB）
- AI 对话首次输出 `<!--PRACTICE-->` 时设置 `diagnosticsCompleted = true`
- 咖啡馆入口按钮判断 `diagnosticsCompleted`：
  - false → 非「今日探险」入口显示 🔒 + 覆盖 `cursor-not-allowed`
  - 点击弹出 toast：**「先和海小喵聊聊吧，看看今天从哪里开始探险～」**
- 「今日探险」入口加 🔥 标记 + 奖励倍率标签

### 1b. 每次登录引导

- `diagnosticsCompleted === true` 后不再锁入口
- 「今日探险」按钮上显示浮动标记「双倍碎片」
- 其他入口显示半透明标签「×1/5」（直接进入的惩罚倍率）

### 1c. AI 跳转追踪

- 新增 store 字段: `diveFromAdventure: boolean`
- 从 AdventureChat 点「去潜水练一练」时设 `true`
- DiveMath 结算时检查 `diveFromAdventure`：
  - true → 全额碎片，结算后设回 false
  - false → 1/5 碎片

### 1d. 奖励规则看板

- 咖啡馆底部加 `🎁 奖励规则` 小按钮
- 点击弹出 Modal 显示规则（碎片倍率、答错倒扣、今日探险奖励）

## 二、潜水算术修复

### 2a. 答错提示隐藏精确位置

**组件**: `DiveMath.tsx`

**改前**:

```ts
setHint({ dir: step.to > step.from ? "up" : "down", to: step.to });
```

虚线两头标出起止点，等于直接告诉答案。

**改后**:

```ts
setHint({ dir: step.to > step.from ? "up" : "down", to: null });
```

`to` 传 null → SVG 层只画方向箭头不标注终点位置。

### 2b. 答错倒扣

**改前**: 过关无条件 `addFragments(1)`

**改后**:

```ts
const wrongCount = /* 本关累计答错次数，从新状态 wrongCount 读 */;
const earned = Math.max(0, 1 - wrongCount * 0.1);
const final = Math.floor(earned * (diveFromAdventure ? 1 : 0.2));
if (final > 0) addFragments(final);
```

- 新增组件内状态 `wrongCount`，每次 `evaluate()` 答错时 +1
- 答错 ≥ 10 次 → 0 碎片
- 倍率在结算时应用

### 2c. 数值显示

过关结算弹窗中新增一行小字：

- 答错 0 次：「完美过关！🌟 ×1」
- 答错 1-3 次：「答错了 N 次，奖励 ×{0.9-0.7}」
- 答错 ≥ 10 次：「答错太多，这次没有碎片哦。再试一次吧！」

## 三、今日探险碎片奖励

### 3a. 什么是「一轮」和「过关」

- **一轮** = 孩子发 1 条消息 + 海小喵回复 1 条（不是 1 道题）
- **过关** = AI 输出 `<!--PRACTICE-->`（无论是因为孩子真正想通，还是聊到 4 轮封顶被送走，都算过关）
- system prompt 规定每个知识点最多 4 轮对话，4 轮后强制 `PRACTICE`
- 孩子可能在一个知识点内答了 7 道题（每轮可能涉及追问），但只要 AI 最终输出 PRACTICE 就算「过了一关」

### 3b. 每轮对话给 0.5 碎片

**组件**: `AdventureChat.tsx`，`send()` 函数

`addFragments()` 接受整数。使用 `useRef(0)` 累加 0.5：

```ts
const fragPending = useRef(0);

// 每次 AI 成功回复后（不含 PRACTICE 且不含开始消息）
fragPending.current += 0.5;
if (fragPending.current >= 1) {
  addFragments(Math.floor(fragPending.current));
  fragPending.current -= Math.floor(fragPending.current);
}
```

仅当累加满 1 时才真正调用 `addFragments()` 并 toast。

### 3c. 突破奖励

已存在 `parseRewardTag` → `addPearls`。只需追加碎片：

```ts
if (rewardGained > 0) {
  addPearls(rewardGained);
  addFragments(2);
  showToast("pearl", rewardGained);
}
```

### 3d. 跳转奖金

`PRACTICE` 标记检测到后 → `addFragments(3)` + toast「诊断完成！去练一练吧 🌟+3」

## 四、古深海遗迹修复（C 方案）

### 4a. 格子定义明确目标

**组件**: `FractionPearls.tsx`

每个可放置的格子增加 `targetNumerator` 和 `targetDenominator` 字段。格子显示文字：「把等于 1/2 的圆放进来」。

### 4b. 放错弹回

拖放完成后检查：拖入的圆的分数值是否等于格子的目标值

- 等于 → 圆吸附定位 + 触发正确流程
- 不等于 → 圆弹回原位（CSS transition `transform` + `opacity`）

弹回动画：圆放大 1.2 倍 → 淡出 → 回到原位置 → 恢复

### 4c. 放对后朗读

```ts
const text = `${childFraction} 等于 ${targetFraction}，它们代表一样多的东西`;
speak(text); // 调用 TTS
```

朗读期间「下一步」按钮 disabled + 显示文字「听海小喵说完…」

TTS 朗读完毕 → 按钮恢复 → 可点击进入下一关

### 4d. 文案优化

- 格子提示从纯数学改为海底语境：「把等于 1/2 珍珠大小的圆放进来」
- 放对后文案：「1/2 颗珍珠 = 2/4 颗珍珠，大小一样，只是切法不同」
- 使用海底客栈/上古石碑的视觉语境

## 五、全局倍率系统

### 5a. 今日探险通关数

**Store 新增**:

```ts
todayAdventureCount: number; // 今天完成 PRACTICE 的次数
```

- 每次 AI 回复中检测到 `<!--PRACTICE-->` → `todayAdventureCount += 1`
- `useLoginCheck` 检测到跨天时重置为 0
- 不持久化（每天重新算）

### 5b. 倍率规则

| 今日探险通关数 | 全局倍率 | 含义                         |
| -------------- | -------- | ---------------------------- |
| 0              | ×0.5     | 今天还没聊，惩罚通道         |
| 1              | ×1.5     | 聊通了一个知识点，奖励通道   |
| 2+             | ×2.0     | 聊通了两个，最高倍率（封顶） |

### 5c. 受倍率影响的活动

- 潜水算术（非 AI 跳转入口）
- 游戏角（BubbleJump + ShellCollector）
- 隐藏菜单（午夜守则等）
- 贝壳图鉴中碎片相关操作

**不受影响**: 珍珠奖励、今日探险自身碎片、兑换操作

### 5d. 全局倍率计算函数

```ts
// src/engine/rewardEngine.ts 新增
export function getGlobalMultiplier(todayAdventureCount: number): number {
  if (todayAdventureCount >= 2) return 2.0;
  if (todayAdventureCount >= 1) return 1.5;
  return 0.5;
}
```

各活动结算时调用此函数，乘以自身基础碎片。

### 5e. 咖啡馆横幅

`CafeHall.tsx` 顶栏下方固定横幅，实时显示当前倍率：

| todayAdventureCount | 横幅                                    |
| ------------------- | --------------------------------------- |
| 0                   | 🎯 今天还没探险哦！所有活动碎片 ×0.5    |
| 1                   | 🔥 已过 1 关！所有活动碎片 ×1.5         |
| 2+                  | 🎉 已过 2 关！所有活动碎片 ×2.0（最高） |

## 六、奖励规则看板

### 6a. 触发方式

咖啡馆底部固定图标 `🎁 奖励规则`，点击弹出 Modal。

### 6b. Modal 内容

Modal 内分为三个区块，用简洁卡片展示：

**区块 1：碎片怎么赚**

- 💬 今日探险每轮对话 +0.5
- 🤔 真正想通一步 +2 碎片 +1 珍珠
- 🏁 聊通一个知识点 +3 碎片
- 🏊 潜水算术过关 +1 碎片（答错扣减）
- 🎮 游戏角按得分结算
- 🐚 隐藏关卡按规则结算

**区块 2：倍率怎么算**

- 今天没聊通关 → ×0.5
- 聊通 1 关 → ×1.5
- 聊通 2+ 关 → ×2.0
- 从今日探险直接跳转 → 全额（不受倍率影响）

**区块 3：答错扣减**

- 潜水算术每答错 1 次 → 扣 0.1 碎片
- 答错 10 次以上 → 0 碎片
- 古深海遗迹放错 → 圆弹回，不扣碎片

### 6c. 数据结构

```tsx
// CafeHall.tsx 内常量
const RULES = [

  { emoji: "🤔", title: "真正想通一步", desc: "+2 碎片 +1 珍珠" },
  ...
];
```

## 九、验证

1. **首次使用流程**：清除 IndexedDB → 进咖啡馆 → 除今日探险外全部 🔒 → 点 🔒 入口弹 toast → 横幅 ×0.5
2. **倍率联动**：完成 1 次 PRACTICE → 横幅变为 🔥 ×1.5 → 进游戏角玩一局 → 结算碎片 ×1.5
3. **倍率封顶**：完成 2 次 PRACTICE → 横幅 🎉 ×2.0 → 潜水和游戏都 ×2.0
4. **跨天重置**：模拟跨天 → todayAdventureCount 归零 → 横幅回到 ×0.5
5. **答错不给答案**：潜水算术故意拖错 → 虚线只显示方向 → 反复拖错 12 次 → 过关后 0 碎片（即使全局 ×2.0，0×2=0）
6. **遗迹不刷关**：把 2/4 圆拖进「等于 1/3」格子 → 圆弹回 → 放对后 TTS 朗读 → 下一步才可用
7. **奖励规则看板**：点 🎁 → Modal 弹出 → 三区块内容正确
