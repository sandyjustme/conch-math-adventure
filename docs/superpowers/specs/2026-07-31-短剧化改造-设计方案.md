# 短剧化改造 · 设计方案

> 日期：2026-07-31
> 状态：**待验证** —— 本方案的动工前提是 `2026-07-31-试播三集.md` 的测试通过
> 背景：v2 奖励驱动模型经约 3 周真实使用被证伪（详见文末「为什么推翻 v2」）

---

## 0. 一句话

**不把数学做成游戏，把数学做成她要追的下一集。**

孩子的全部兴趣是「刷短剧、看电视、吃」。三样的共同点是零主动投入、即时回报、不需要做决定。游戏要求的恰好相反：操作、练技能、承受失败、追目标。所以问题不是游戏化做得不够好，是品类选错了。

---

## 1. 主循环

### 现在（v2）

```
大厅 6 张卡 → 她选最便宜的一条 → 刷珍珠 → 兑换
```

**6 张卡本身就是问题**：它是认知负荷，是选择成本，更是套利空间——只要存在多条路径通向同一种货币，她就会算出最便宜的那条并且只走那条。事实证明她算对了。

### 新的（v3）

```
打开 app → ▶ 继续听（第 7 集）→ 听 → 主角遇到困境（题）→ 她替主角做选择
  → 剧情按她的选择继续 → 集末钩子 → 停
```

**没有大厅，没有玩法选择，没有难度选择。** 打开就是继续听。

> **设计铁律 1：取消选择即取消套利。**
> v2 死于"她有得选，所以她优化"。v3 主界面只有一个按钮。

---

## 2. 一集的结构

| 段落         | 时长     | 作用                                     |
| ------------ | -------- | ---------------------------------------- |
| 接钩子       | ~10 秒   | 回应上集悬念，但**只回应一半**           |
| 推进         | 40–60 秒 | 剧情前进，主角走进困境                   |
| **困境即题** | —        | 主角必须做一个判断，这个判断就是数学     |
| 分叉         | 20–30 秒 | 她选完，剧情按选择继续（**两条都继续**） |
| 新钩子       | ~15 秒   | 吊住下一集                               |

**总长 1.5–2 分钟，正文 300–450 字**，火山 TTS 朗读约 90–120 秒。

---

## 3. 题怎么嵌 —— 全案最关键的一节

沿用 `reskinSoup` 已验证的「硬约束 + 自检 + 程序化二次校验」模式。

### 硬约束（违反任意一条即作废重生成）

1. **题必须是主角的行动选择，不能是旁白的提问。** 禁止出现"请问""计算""答案是""等于多少"
2. **题面不许出现数学术语**：负数、正数、绝对值、相反数、比大小、加减乘除、数轴
3. **两个选项必须是剧情动作，不能是裸数字**
   - ✅ 「按 −3 那一层」 / 「按 −7 那一层」
   - ❌ 「A. −3」 / 「B. −7」
4. **答案必须能从剧情线索推出来**，不能只靠纯计算
5. **一集只考一个知识点**

> **设计铁律 2：题必须是"她替主角做决定"，不是"系统在考她"。**
> 这一条绕开的是 self-worth protection——运营中观察到的"简单她嫌弃、难了她又觉得太难"，两头都拒绝说明拒绝的不是难度，是被评价本身。当被评价的对象从"我行不行"变成"这段好不好看"，这个防御就失效了。

---

## 4. 答错怎么办 —— 答错不阻断

> **设计铁律 3：答错不重来、不扣分、不弹"再想想"。剧情继续走，只是走向更糟的分支。**

- 答错 → 剧情继续，但代价更大 / 更吓人 / 悬念更强
- **教学发生在错误分支里**：通过剧情把正确逻辑说破（同桌点破、主角事后醒悟），是叙事不是讲解
- 同一知识点在后续 2–3 集换情境再出现（变式），不是重考同一题

**这一条直接消灭 v2 最致命的退出理由**：运营中"做题超过 3 题没获得奖励就立刻放弃"。在 v3 里每一次选择都推动故事，不存在"白做了"。

---

## 5. 进度体系 —— 只剩一个数字

### 全部丢掉

碎片、珍珠、游戏次数、全局倍率、连续登录奖励、藏宝图点亮、关卡、六维雷达（对她展示的部分）

### 只留

**集数。** "你追到第 12 集了。"

跟她刷短剧的心理模型完全一致，不需要任何解释——符合"每一处 UI 都要自解释"的原则。

### 后台仍然记录（不对她展示）

`answerRecords`（沿用现有结构）+ 知识图谱索引。用途有二：给家长看板；给生成器决定下一集考什么。

---

## 6. 「吃」挂在哪

### 现在的问题

卡点在"赚够珍珠"，珍珠来自答对，所以她必然优化。**数学成了饭的价格，家长成了收费的人。**

### 新的挂法

**按剧情节点解锁**：一季（5 集）追完 → 解锁一次点单权。

**为什么天然防刷**：集数是内容，内容一天只更新固定几集。她刷不出第 6 集。
**内容的稀缺性就是防刷机制，不需要写任何反作弊代码。**

性质也变了：吃从"数学的对价"变成"追完一季的庆祝"。

### 过渡方案（避免突然撤掉唯一驱动力）

第一周保留珍珠，但**珍珠只从"看完一集"来，不从"答对"来**——答对答错都给。她立刻失去优化空间，同时不会感到被剥夺。第二周起改为按季解锁。

## 7. 内容生产

这是本路线的真实成本：游戏可以重复玩，剧情看完就没了，必须持续供应。

### 生成器输入

- 世界设定（固定）：人设、世界观、守则体系
- 已发生剧情摘要（滚动压缩，控制 token）
- 本集知识点（从 `knowledgeGraph.ts` 取）
- 上一集的钩子（**必须接住**）
- 上一集她答对还是答错（决定接哪条分支）

### 输出 JSON

```jsonc
{
  "epNo": 7,
  "title": "第七层的灯",
  "openText": "…接住上集钩子，只回应一半…",
  "bodyText": "…推进到困境…",
  "choice": {
    "prompt": "…主角必须做的决定…",
    "optionA": "按 −3 那一层", // 剧情动作，不是裸数字
    "optionB": "按 −7 那一层",
    "correct": "A",
  },
  "branchRight": "…答对的剧情…",
  "branchWrong": "…答错的剧情，必须继续，并在其中说破正确逻辑…",
  "hookText": "…集末钩子，不以句号结尾…",
  "nodeId": "K7",
  "selfcheck": {
    "no_math_terms": true,
    "choices_are_actions": true,
    "hook_present": true,
    "wrong_branch_continues": true,
    "one_node_only": true,
  },
}
```

### 程序化二次校验（不信 AI 自检，照抄 reskinSoup 的做法）

| 检查     | 规则                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 术语扫描 | 正则命中 `负数\|正数\|绝对值\|相反数\|比大小\|计算\|答案\|等于` → 作废 |
| 选项形态 | `optionA/B` 为纯数字字符串 → 作废                                      |
| 钩子存在 | `hookText` 为空或以 `。` 结尾 → 作废                                   |
| 错误分支 | `branchWrong` 为空 → 作废（绝不允许阻断）                              |
| 长度     | 正文总字数不在 300–450 → 重生成                                        |

作废时回落到预写的备用集，**绝不能让她打开 app 看到"生成失败"**。

---

## 8. 知识点覆盖与排播

- **一季 5 集，覆盖 3 个知识点**（2 个新 + 1 个回炉变式）
- 20 个有理数知识点 ≈ **8–10 季 ≈ 40–50 集**
- 每天更新 2 集 → 约 25 天走完第一章

**季的结构（单元剧 + 主线）**

- 每季：独立小危机 + 解决（给她完成感）
- 主线跨季推进：−7 层是什么 / 同桌是谁 / 怎么回到 0 层

## 10. 防刷

不需要专门写。**内容稀缺 = 天然防刷。**

唯一要守的一条：**重听一集不再发奖**。发奖点绑定 `epNo` 首次完成。

（对照 v2 的三个刷分口子：潜水关卡无去重、规则怪谈无冷却、都是因为"同一奖励可被无限次触发"。v3 的奖励绑定在一次性内容上，结构上不成立。）

---

## 11. 风险与未决

| 风险                   | 应对                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------- |
| 试播不通过             | **本方案作废**，不写任何代码。这是第一道闸门                                                 |
| 内容跟不上             | 预写 10 集垫底；生成失败回落备用集                                                           |
| 她跳过剧情只点选项     | 奖励绑"看完一集"而非"答对"，跳过就没有意义；若仍发生，说明故事不够好，是内容问题不是机制问题 |
| 学习效果无法验证       | 后台 `answerRecords` 照旧累积，家长看板看知识点正确率；**但不对她展示**                      |
| 剧情消耗快于知识点推进 | 一集只考一个点是硬约束；宁可剧情慢，不可一集塞两个点                                         |

**未决**：故事线走到 20 个知识点都覆盖完之后怎么办（第二章「整式的加减」是否延续同一世界观）。等第一季跑完再定，现在定太早。

## 附：为什么推翻 v2

约 3 周真实使用的观察结果：

- 孩子发现并持续利用规则怪谈的刷分漏洞，专注挣珍珠换食物
- 今日探险、潜水算术两条核心学习路径**视而不见**
- 今日探险：简单嫌弃，难了说太难（两头都拒绝）
- **做题超过 3 题没拿到奖励就立刻放弃**，转去规则怪谈
- 古深海遗迹、海龟汤基本不打开
- 游戏角觉得不好玩
- 若非家长用"吃饭要用珍珠兑"硬卡，完全没有动力做任何题
- 最终结果：**有理数 20 个知识点点亮 6 个，过关 4 个**

**结论**：奖励驱动模型对该用户不仅无效，而且有害——它给了她一个可以赢的优化游戏，而她赢了。堵漏洞不能解决问题，只会让"税"变贵、抵触变强。

**唯一被验证的正面信号**：她每天会主动打开 app。容器是成立的，里面装的东西不成立。
