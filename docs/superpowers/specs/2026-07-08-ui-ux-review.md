# UI/UX 设计审查报告

> 项目：海螺喵数学探险
> 日期：2026-07-08
> 阶段：MVP 初版（本地运行）
> 审查人：Claude Code

---

## 执行摘要

**整体评价：** 项目的设计系统（配色、字体、圆角风格）有一个清晰的海底主题方向，咖啡馆大厅的五宫格布局直观简洁。但产品目前处于"功能骨架"阶段——核心交互流程可走通，视觉反馈和易用性打磨严重不足。对于一个目标用户是"厌学初一学生"的产品，**趣味性和即时反馈是两个最关键的体验指标**，这两点当前严重缺失。

**关键优势：**

- 海底主题配色统一（天空蓝→深海蓝），视觉风格一致
- 咖啡馆大厅卡片式导航，入口清晰
- 语音输入已预留（🎤 按钮）

**需要立即关注的关键问题：**

- 无任何入场动画或微交互反馈（答对、升级、获奖励均无视觉提示）
- 探险页的交互层次混乱：数轴、气泡选项、聊天三种交互谁主谁次不明确
- 游戏虽然加了渐变和粒子，但反馈单一（只有音效），无连击、动画、分数飞入等
- 大量小字（11px、10px），对儿童阅读极不友好

**可访问性达标等级：** 未达标（WCAG A 级有多项违规）

## 一、交互体验评估

### 1.1 反馈系统：HIGH

**问题：** 整个应用几乎只有音效反馈。孩子答对一道题、获得珍珠、升级到新关卡——这些关键时刻没有任何视觉反馈（动画、粒子、弹窗、分数飘入）。

**用户影响：** 厌学孩子需要"看到自己的进步"。音效可能被关掉，视觉反馈是唯一保证能被感知的反馈通道。

**建议：**

```
答对 → 海小喵头像跳一下 + 绿色波纹扩散
获珍珠 → 珍珠从屏幕中央飞入右上角计数器（轨迹动画）
升级 → 全屏短暂烟花/星星粒子 + "恭喜解锁新岛屿！"弹窗
连续答对 → 连击计数器显示（×2, ×3...）
```

### 1.2 探险页交互层次：CRITICAL

**问题：** 同一屏幕上有三个竞争交互：数轴拖动、气泡点击、底部三个按钮。没有视觉引导告诉孩子"现在应该干嘛"。

**用户影响：** 厌学孩子面对选择会感到困惑——我该拖猫还是点气泡还是打字？困惑→弃用。

**建议：**

```
方案 A：分步引导模式
  Step 1: AI 发问 → 数轴高亮 + 提示"拖动小猫回答"
  Step 2: 孩子拖动到答案 → 数轴锁定，确认按钮闪烁
  Step 3: 提交 → 反馈动画
  Step 4: 进入下一问

方案 B：模式切换
  默认"手势模式"：只看数轴和气泡，没有打字框
  点击💬才展开打字，用完自动收起
```

### 1.3 游戏角反馈：HIGH

**问题：** 两款游戏虽然有音效，但得分只有数字变化。没有连击文字、没有分数飞入动画、没有排行榜或最佳成绩。第一局和第十局体验完全一样。

**建议：**

- 得分时数字放大 + 弹跳动画
- 连续答对显示 "连击 ×3！"
- 每局结束显示"新纪录！"如果破了个人最佳
- 贝壳碎片获得时：从中间飞出到右上角计数器的轨迹动画

### 1.4 咖啡馆大厅：MEDIUM

**问题：**

1. 五宫格布局中，第一行是满宽的"今日探险"，第二行是 2×2 的四宫格。这个布局不直观——孩子可能找不到"兑换吧台"。
2. 卡片上的描述文字太小（`text-xs`），且部分使用浅色文字（`text-slate-500`）。
3. 兑换吧台的脉冲动画 `animate-pulse` 可能分散注意力。

**建议：**

- 考虑把五宫格改为 2×3 或 3×2 的均等网格
- 卡片描述文字至少 `text-sm`（14px）
- 兑换吧台不用脉冲，改用静态的徽标（如"可兑！"小标签）

### 1.5 藏宝图交互：MEDIUM

**问题：** 4 列网格排列 20 个岛屿，每格非常小。只能看不能点——点岛屿应该能跳转到对应关卡的探险。

**建议：**

- 改 3 列，让每个岛屿更大
- 已解锁岛屿可点击，跳转到对应关卡的探险对话
- 当前所在岛屿有呼吸光效

## 二、视觉设计评估

### 2.1 字体大小：HIGH

**问题：** 多处使用 10px-11px 文字：

- 藏宝图知识点的编号 `text-[10px]`
- 探险页底部提示 `text-[11px]`
- 游戏角描述文字 `text-xs`（12px）
- 进度条知识点标签 `text-[10px]`

**用户影响：** WCAG 建议正文最小 16px。对于初一学生（12-13 岁），小字体增加阅读疲劳。如果孩子在手机上使用，这些字几乎是不可读的。

**建议：**

- 所有 UI 文字 ≥ 13px
- 提示/辅助文字 ≥ 12px
- 使用 `rem` 单位而非固定 `px`

### 2.2 颜色对比度：MEDIUM

**问题：**

- `text-slate-500` (#64748B) 在 `#EAF6F6` 背景上：对比度约 3.8:1，低于 WCAG AA 要求的 4.5:1
- `text-slate-400` (#94A3B8) 在浅色背景上更差：约 2.5:1
- 游戏内白色文字在渐变背景上部分区域对比度不足

**建议：**

- 辅助文字改用 `text-slate-600`（#475569）
- 在浅色背景上不要使用 `slate-400`
- 用 WebAIM Contrast Checker 逐色验证

### 2.3 空白状态设计：MEDIUM

**问题：** 贝壳图鉴的稀有贝壳区显示"还没有稀有贝壳，完成里程碑来获得第一只吧！"——这是纯文字，冷冰冰的。游戏角未解锁游戏也只是一个 🔒。

**建议：**

- 空贝壳区：显示一个虚线框 + 浅色猫猫剪影 + "完成第一个关卡后，这里就会出现你的第一只稀有贝壳！"
- 未解锁游戏：显示游戏的剪影/轮廓 + 解锁条件（如"学完有理数加法后解锁"）

### 2.4 动画/过渡：LOW

**问题：** 视图切换没有任何过渡动画。从咖啡馆到探险到游戏角，都是硬切。Modal/弹窗也没有出现动画。

**建议：**

- 视图切换加一个简单的 fade-in（Tailwind `animate-in fade-in` 或 CSS transition）
- 弹窗/面板从下方滑入

### 2.5 加载状态：LOW

**问题：** AI 回复加载时只显示"海小喵正在思考…"文字。30 秒游戏结束后没有倒计时读秒的紧迫感（最后 5 秒应该有视觉变化）。

**建议：**

- AI 加载：海小喵头像带呼吸动画 + 三个跳动的点
- 游戏最后 5 秒：倒计时变红 + 屏幕边缘泛红

## 三、可访问性评估

### 3.1 WCAG 违规模板

| 等级 | 准则             | 问题                                                                        | 严重程度 |
| ---- | ---------------- | --------------------------------------------------------------------------- | -------- |
| A    | 2.4.7 焦点可见   | 所有按钮无 `focus:ring` 或自定义焦点样式（Tailwind 默认 reset 了 outline）  | CRITICAL |
| A    | 1.3.1 信息和关系 | 无 `<main>`、`<nav>`、`<header>` 等语义化标签，页面结构无法被屏幕阅读器理解 | HIGH     |
| A    | 1.1.1 非文本内容 | Mascot 图片无有意义的 alt 文本（"海小喵"过于简单）；数轴 SVG 无文本替代     | HIGH     |
| A    | 2.5.5 目标大小   | 进度圆点 2.5px 远小于 44px 最小触摸目标                                     | HIGH     |
| A    | 3.3.2 标签或说明 | 输入框使用 placeholder 作为唯一标签（无 `<label>`）                         | MEDIUM   |
| AA   | 1.4.3 对比度     | 多处文字对比度 < 4.5:1                                                      | MEDIUM   |
| A    | 2.4.2 页面标题   | 页面切换时 `<title>` 不更新（始终显示"海螺咖啡馆"）                         | MEDIUM   |
| AA   | 1.4.4 文本缩放   | 使用固定 px 而非相对单位，200% 缩放时布局可能破损                           | LOW      |
| A    | 3.2.3 一致导航   | 部分页面的返回按钮行为不一致（有的是 🏠 回大厅，有的是 ← 回上级）           | LOW      |

### 3.2 键盘可访问性

- **无可见焦点指示器**：这是最大的无障碍问题。Tab 键无法看到当前聚焦的元素。
- **Canvas 游戏完全不可键盘操作**：BubbleJump 只有键盘方向键支持，但无 Tab 可达的焦点；ShellCollector 完全只有点击
- **数轴拖动不可键盘操作**：OceanLine 只能鼠标/触屏

## 七、总结

当前产品做到了"能跑通"——所有页面、状态、API 都连起来了。但从"能跑通"到"孩子愿意用"，中间差的是**反馈、节奏和视觉糖**。对于厌学孩子来说，这些"糖"不是可有可无的装饰，而是维持注意力和动力的基础设施。

核心原则：**每一次交互都要有看得见的回应。**
