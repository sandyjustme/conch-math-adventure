## 二、安全 ⚠️

### 2.1 API Key 暴露前端（中风险）

`VITE_DEEPSEEK_API_KEY` 在客户端直接调用 DeepSeek API（`ai.ts:38`），意味着：

- Key 会打包进 `dist/assets/index-*.js`，任何人打开浏览器 F12 就能看到
- 如果有人拿到你的构建产物，Key 直接泄露

**已有但未启用的修复**：`server/api/chat.ts` 是一个完整的服务端代理（Key 存在 `process.env`，前端只调 `/api/chat`）。把它用起来即可消除此风险。

### 2.2 环境变量

- `.env` 已在 `.gitignore` ✅
- `.env.example` 模板存在 ✅

### 2.3 输入

- 用户输入经 React JSX 自动转义 ✅
- 无文件上传、无 URL 参数注入面 ✅
- DeepSeek API 回复直接渲染为 HTML——如果模型被 prompt injection 诱导输出 `<script>` 标签，React 会转义，安全 ✅

## 三、鲁棒性

### 3.1 无 Error Boundary（高风险）

整个应用没有 `ErrorBoundary` 组件。任何单个 React 组件崩溃（比如 DiveMath 里除零）→ 整页白屏。

### 3.2 空 catch 吞错（6 处）

```typescript
} catch {   // 无任何日志
```

分布在 AdventureChat、SoupKitchen、DiveMath、ai.ts。生产环境出错时完全无迹可查。

### 3.3 无加载骨架

所有异步操作只显示文字 "海小喵正在思考…" 或 "海小喵在熬汤…"。网络慢时体验差。

### 3.4 无离线/降级处理

IndexedDB 持久化只存状态，不缓存 API 响应。断网 = 不能用。

## 四、代码质量

### 4.1 类型系统

- `strict: true` ✅
- React 18 运行时 + @types/react 19 → 版本差异，但构建通过
- 1 处 `any`：`usePersistence.ts:34` → `setItem(key, value: any)`
- 所有视图路由有完整 View 类型约束 ✅

### 4.2 残留物

- `console.log('知识图谱验证通过')` — `validateGraph.ts:57`，生产构建应移除
- 无 dead imports、无未使用变量

### 4.3 状态管理

- Zustand store 167 行，单一 store 合理（当前规模无需拆分）
- `answerRecords` 数组无限增长——长期使用会撑爆 IndexedDB。应加上限（如保留最近 500 条）

### 4.4 组件结构

- 无循环依赖 ✅
- 无组件超过 500 行（最大 DiveMath ~550 行，临界但可接受）
- 渲染逻辑和业务逻辑混在同一文件，暂无需拆分

## 七、无障碍
